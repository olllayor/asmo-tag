# Conversation-first UI

The user delegated the visual choice on October 6, 2026: research how Claude Tag handles the problem and use its method. This instruction resolves the earlier A/B/C selection gate. The implementation uses B's task-reading structure and adapts it to the documented Tag flow. It does not claim pixel parity with a logged-in product we have not inspected.

Claude Tag completes shared work in Slack threads. A Configure link under replies opens settings for the current channel. Channel members see General, Tools and access, and Routines surfaces. Organization owners have separate administration and activity surfaces. The public [Claude Academy walkthrough](https://academy.claude.com/courses/introduction-to-claude-tag/expand-what-claude-owns) demonstrates the channel configuration tabs. The [admin guide](https://academy.claude.com/tutorials/claude-tag-admin-guide) describes the separate owner surfaces.

Asmo keeps Telegram as the task conversation. Progress and results carry a stable task ID. Replies steer that task. A task link opens an evidence-led inspection view with findings, sources, ordered events, effects, and exact approvals. Configure opens group settings with General, Tools and access, Memory, and Routines. Owner controls for budgets, audit, and workspace policy appear only to authorized owners or managers.

The Mini App validates Telegram authentication on the server. Client query parameters select a view, not authority. An inaccessible task produces a neutral denial. Missing Telegram authentication shows a launch instruction. It does not substitute a demo identity. A separately selected fixture preview is visibly simulated and uses only invented local records.

Personal connector review goes to its owner privately. The shared task view never contains private connector input or tool results. Its progress can show only a neutral review wait. The exact output and destination are displayed in private before approved sharing. Unavailable private delivery keeps the review pending.

The interface uses the user's black-and-white design rules, dense rows, plain states, visible evidence, and explicit failures. Buttons act on saved revisions. Disable a decision during its request and reload the server's result. A stale preview cannot be approved by changing browser state. Show unknown effects as unresolved work rather than success.

The first Mini App uses authorized task, memory, routine, and policy APIs. Code execution, personal connectors, and unproven ambient behavior remain labeled unavailable until their separate gates pass. A disabled capability is explained by its actual configuration or stage.
